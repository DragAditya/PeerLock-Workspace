04 / Local-first behavior

Offline-first workflow

P2P WORKSPACE · 05

Editing does not wait for the network. The browser restores a durable local replica first, accepts new changes while offline, and later exchanges missing CRDT updates when a reachable room peer returns.

IMPORTANT /
Local persistence preserves work. Synchronization requires both a valid room peer and network connectivity.

01 / RESTORE

Open local replica

The Yjs document is restored from the browser's IndexedDB store before peer synchronization begins.

STATE: LOCAL HISTORY AVAILABLE

02 / EDIT

Continue offline

New rich-text operations remain valid local CRDT updates and are persisted without a live connection.

STATE: NETWORK OPTIONAL

03 / RECONNECT

Discover peers

After connectivity returns, the WebRTC provider can re-establish room peer channels through signaling-assisted setup.

STATE: MISSING UPDATES EXCHANGED

04 / CONVERGE

Merge replicas

Yjs merges compatible updates deterministically so reachable replicas reach the same shared document state.

STATE: EVENTUAL CONSISTENCY

LOCAL-FIRST PRINCIPLE

The browser is the durable editing environment; peer networking replicates the work rather than making the work possible.
